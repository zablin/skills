# 机制

仅当多个重要发现可能共享同一底层机制、关系、瓶颈、反馈或测量过程时使用。

目标不是给每篇论文都造一个“核心模型”。

## 1. 是否存在统一机制

问：

- 多个重要发现是否来自同一条关系？
- 这个机制能否解释不止一个结果？
- 这些发现真的彼此相关，还是只是恰好出现在同一篇论文里？

如果彼此独立，就停止，不强行合并。

## 2. 重建机制

需要时可以使用：

起点 / 输入
→ 关键操作或关系
→ 中间变化
→ 结果
→ 反馈 / 边界

每一个箭头都应该能解释“为什么下一步会发生”。

## 3. 检验解释力

尝试用这个机制解释至少两个不同发现。

如果只能解释一个结果，更适合把它称为局部解释，而不是统一机制。

## 4. 改变一个条件

改变一个关键条件，然后问：

- 哪个环节最先变化？
- 下游结果会怎么变？
- 为什么？

## 5. 区分验证与预测

明确区分：

- 论文直接验证的结果
- 作者解释
- 根据机制得到的合理预测

不要把未测试预测写成论文发现。

## 6. 没有统一机制时

如果不存在统一机制：

- 保留重要独立关系
- 解释它们如何共同构成论文贡献
- 不要为了整齐而强行造公式、流程图或单一叙事
