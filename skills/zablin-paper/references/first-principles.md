# 第一性原理

只有在论文涉及隐藏假设、历史惯例、复杂系统、工程约束，或重新设计“原本被当成固定”的东西时使用。

如果不能带来新的理解，就跳过。

## 1. 拆解系统

把相关系统、方法、流程、假设、指标或设计拆成有意义的组成部分。

不要一上来问“整篇论文的第一性原理是什么”。

## 2. 对每个部分问三个问题

1. **这个部分是固定的吗？**
2. **这个部分是必须的吗？**
3. **它是由客观 / 物理约束决定，还是由历史习惯、制度、惯例或继承设计造成的？**

## 3. 找出真正可变的部分

区分：

- 硬约束
- 必要功能要求
- 历史惯例
- 任意实现选择
- 被误认为固定的假设

## 4. 找真正突破

问：

- 作者改了哪个原本被认为不可改的部分？
- 为什么它其实可以改？
- 哪些硬约束仍然存在？
- 新的边界或代价是什么？

只有当这套拆解真正揭示了有用区别时，才称为第一性原理分析。
